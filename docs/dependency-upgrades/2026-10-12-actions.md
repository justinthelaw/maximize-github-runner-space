# Action runtime dependency review - 2026-10-12

This supplements the [main ledger](2026-10-12.md). All three actions use the
latest stable upstream release. Their published bundles are immutable; project
npm overrides cannot modify them. Retain supported actions and revisit deferred
leaves when upstream rebuilds a supported release. No speculative private forks.

Tables inventory production declarations from the exact pinned upstream lockfiles
(excluding development-only packages). They are not a claim that every declared
package is reachable in a compiled entrypoint. Registry targets were checked on
2026-10-12. Bundled behavior and advisory evidence are distinguished below.

## Shipped code and security

- setup-node 7.1.0 ships vulnerable smol-toml scanning code in both entrypoints:
  [setup](https://github.com/actions/setup-node/blob/949feb2413d6458794dcd2491c4babbbce0c15c1/dist/setup/index.js#L96991-L97055)
  and [post](https://github.com/actions/setup-node/blob/949feb2413d6458794dcd2491c4babbbce0c15c1/dist/cache-save/index.js#L91597-L91661).
  Official npm 1.7.1 struct.js matches the bundled module after ncc normalization;
  its quadratic scan is fixed in 1.9.0+.
  These workflows use explicit `node-version: "22"`, not a TOML version file.
  This limits the relevant input path; it does not patch the action.
  [Advisory](https://github.com/advisories/GHSA-r4xh-jqrq-34v2)
- setup-node's brace-expansion bundle is the patched 5.0.12 implementation,
  corroborated by exact source and behavioral checks. A prior review's 5.0.8
  claim does not describe this pin. The upgrade removes old 1.x/5.0.6 declarations
  and upgrades its Undici declaration from 6.27.0 to 6.29.0.
  [Shipped brace implementation](https://github.com/actions/setup-node/blob/949feb2413d6458794dcd2491c4babbbce0c15c1/dist/setup/index.js#L47105-L47122)
- checkout 7.0.1 declares Undici 6.27.0 (six advisory records; fixes in 6.28.1+).
  Official-tarball comparison matches 89 of 99 Undici source modules, including
  retry, cookie and WebSocket security-critical code, in checkout and both
  setup-python entrypoints. This confirms shipped code, not workflow exploitability.
  [Bundle](https://github.com/actions/checkout/blob/3d3c42e5aac5ba805825da76410c181273ba90b1/dist/index.js)
- setup-python 7.0.0 declares brace-expansion 1.1.15/5.0.6, Undici 6.27.0,
  and fast-xml-parser 5.9.3. Audit returns 19 affected range records (13 distinct
  advisory IDs). Exact-normalized source matches brace 1.1.15 in both entrypoints and
  brace 5.0.6 in setup. The supplied npm tarball integrity was verified. Official fast-xml-parser 5.9.3 DocTypeReader and OrderedObjParser source
  matches both bundles after ncc normalization. Repeated DOCTYPE calls reset
  document-wide entity limits: [call](https://github.com/actions/setup-python/blob/5fda3b95a4ea91299a34e894583c3862153e4b97/dist/setup/index.js#L61255-L61259),
  [reset](https://github.com/actions/setup-python/blob/5fda3b95a4ea91299a34e894583c3862153e4b97/dist/setup/index.js#L59512-L59524).
  [Setup bundle](https://github.com/actions/setup-python/blob/5fda3b95a4ea91299a34e894583c3862153e4b97/dist/setup/index.js)

| Retained dependency | Considered fix | Outcome / retry condition |
| --- | --- | --- |
| setup-node: smol-toml 1.7.1 | 1.9.0+; latest 1.9.1 | Deferred: latest action bundles affected code; retry a supported rebuilt action. |
| checkout/setup-python: Undici 6.27.0 | 6.28.1+; supported 6.x latest 6.29.0 | Deferred: action-owned bundle; retry upstream release. [Advisory](https://github.com/advisories/GHSA-rfgv-xxqx-mfg5) |
| setup-python: brace-expansion 1.1.15/5.0.6 | 1.1.21 / 5.0.12 | Deferred: both bundled families need upstream refresh. [Advisory](https://github.com/advisories/GHSA-mh99-v99m-4gvg) |
| setup-python: fast-xml-parser 5.9.3 | 5.10.1+ | Deferred: latest parent retains affected implementation; retry supported rebuild. [Advisory](https://github.com/advisories/GHSA-8r6m-32jq-jx6q) |

Current parent releases are already selected. Forcing leaves in this repository
would leave downloaded action bundles untouched. Replacing setup/checkout with
custom shell code would introduce a new authentication/cache/platform maintenance
surface rather than a supported dependency migration. CI success does not clear
these upstream security deferrals; they remain explicit release risks.
