## Verification and release gates

The smartquote migration was tested on Python 3.14.7 with released wheels,
five fixtures and two passes per tool (20 CLI invocations): Markdown prose,
fenced YAML and blockquotes; clean ASCII; CRLF without EOF; the full quote
set; and custom quote codepoints. Old/new outputs were byte-identical,
return codes matched, second runs were idempotent, and stderr stayed empty.
The released hook definitions have identical `fix-smartquotes` IDs, entries,
Python language, and text file targeting. Both implementations pass on
Python 3.14.7; migration is motivated by deprecation and maintained successor
continuity, rather than an invented legacy Python failure.

Completed locally: `npm ci --ignore-scripts`; `npm test` (305 passed,
three Windows-native tests skipped); `npm run format:check`;
`npm run check-dist`; `git diff --check`; and all pre-commit/pre-push hooks
under Python 3.14.7 and pre-commit 4.6.2. The environment's npm 11.9.0
failed hook initialization with EALLOWGIT; optional npm 12.1.0 resolved that
local tool issue without adding a project pin. Sandbox process restrictions
blocked the unchanged timeout tests and git subprocess inspection; both
passed with process restrictions lifted. These changes preserve cleanup
inputs, safety rules, adapters, and runner label matrices.

The existing [compatibility workflow](../../.github/workflows/compatibility.yml)
owns the 18-label bounded sweep and dispatch-only seven-class default-max
matrix. The current-main [scheduled sweep](https://github.com/justinthelaw/maximize-github-runner-space/actions/runs/36453101531)
passed all 18 labels at commit `1c13a10f18d78f8872b11e5e790283c74ec7ce99`;
its generated-dist and default-max jobs were skipped because it was scheduled.
That result does not establish manual default-max validation on this branch.
A release still requires current-head CI/review and both native matrices.
